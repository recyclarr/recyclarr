# ADR-013: Refitter generates every OpenAPI client

- **Scope:** `src/Recyclarr.Client`, `Refitter.MSBuild` in `Directory.Packages.props`

## Context

Recyclarr generates one client from an OpenAPI spec: its own server API, which the CLI consumes
through `Recyclarr.Client`. Sonarr and Radarr contracts are hand-written (ADR-006). The self-client
spec is OpenAPI 3.1, committed at `src/Recyclarr.Server/Recyclarr.Server.json`. The CLI renders
server responses directly, so required fields must stay non-nullable, and tests substitute Refit
interfaces with NSubstitute.

Refitter reads specs through NSwag and its schema library NJsonSchema, which has caused load
failures (object-valued `x-enumDescriptions` ([NJsonSchema#1943][njs-1943]), numeric bounds,
recursive schemas). Kiota, which reads with Microsoft.OpenApi 3.x, was evaluated twice: it first
generated the self-client, and a Kiota 1.36.0 build was trialed again when NJsonSchema broke the
self-client build.

## Decision

Every client generated from an OpenAPI spec MUST be generated by Refitter as Refit interfaces. MUST
NOT introduce a second generator. NJsonSchema failures go to Refitter's maintainer as upstream
fixes; the maintainer already sanitizes specs before NSwag reads them and plans to remove NSwag
([refitter#1310][refitter-1310]).

### Versioning

Each self-API version gets its own `.refitter` configuration, scoped by path regex and emitted into
a version-specific namespace:

```json
{
  "openApiPath": "../Recyclarr.Server/Recyclarr.Server.json",
  "namespace": "Recyclarr.Client.V1",
  "includePathMatches": ["^/api/v1/.*"],
  "multipleInterfaces": "ByTag"
}
```

A v2 client is a second configuration with `^/api/v2/.*` and `Recyclarr.Client.V2`. Consumers pick a
version once, at import or DI registration, and the version segment stays in the Refit route
attribute rather than appearing at every call site. This keeps versions distinguishable for external
consumers without threading the version through every call.

## Rejected Options

- Kiota for all clients. Its 1.36.0 trial loaded the spec but showed lasting costs:
  - Every model property is nullable, including `required` ones, by design
    ([kiota#3846][kiota-3846]; fix planned for v2 with no date, [kiota#3911][kiota-3911]). Every CLI
    renderer read would need a null guard; Refitter with `RespectNullableAnnotations` fails at
    deserialization instead.
  - No interfaces ([kiota#5560][kiota-5560]); tests must fake `IRequestAdapter` or the handler.
  - `anyOf` with a discriminator becomes an intersection wrapper, so the CLI cannot tell which
    polymorphic response it received.
  - Path segments appear at call sites (`client.Api.V3.Qualityprofile`), with no prefix-stripping
    option ([kiota#4004][kiota-4004]).
  - No supported MSBuild integration ([kiota#3005][kiota-3005]).
  - Success status codes are not returned, so callers cannot branch on 200 versus 202.
- Kiota for the self-client only: two generators and a second HTTP client stack
  (`Microsoft.Kiota.Bundle`) for one client.
- A hand-written facade over a Kiota client: extra code to hide the call-site problem only.

## Consequences

- The CLI keeps non-nullable contracts and fails fast on a broken response.
- Refit interfaces stay directly mockable; one configuration format covers all clients.
- Each new self-API version needs its own `.refitter` configuration.
- NJsonSchema stays in the read path until Refitter removes it; its OpenAPI 3.1 support is
  incomplete. Fallback if Refitter stalls: hand-write Refit interfaces from the specs.
- Revisit when Kiota generates non-nullable `required` properties for C#, or if Refitter's NSwag
  removal stalls while NJsonSchema failures keep blocking builds.

## History

- 2026-07-24: Generate the self-client with Refitter instead of Kiota; one generator for all
  clients.
- 2026-10-10: Kiota re-evaluated after an NJsonSchema load failure; stay on Refitter and fix
  upstream.
- 2026-10-16: Refitter 2.3.1-preview.120 fixed object-valued `x-enumDescriptions`
  ([refitter#1336][refitter-1336]); spec workarounds removed.
