# ADR-006: Refit clients generated from Sonarr and Radarr OpenAPI specs

- **Scope:** `src/Recyclarr.Api.Sonarr`, `src/Recyclarr.Api.Radarr`, outbound HTTP in Core and
  Server

## Context

Recyclarr talked to Sonarr, Radarr, and Apprise through Flurl with hand-maintained DTOs. Those DTOs
hid upstream renames and removals, and Flurl's testing library made API calls awkward to fake.
Sonarr and Radarr publish official OpenAPI specs, generated by their own builds, that are the
authoritative API contracts.

## Decision

All outbound HTTP uses Refit interfaces on `HttpClient`.

- Each upstream service with an OpenAPI spec has its own library (`Recyclarr.Api.Sonarr`,
  `Recyclarr.Api.Radarr`). Refitter generates Refit interfaces and contracts from the vendored
  `openapi.json`, limited with `includeTags` to the API areas Recyclarr uses and split with
  `multipleInterfaces: ByTag`. MUST NOT hand-edit generated DTOs; change the vendored spec or the
  `.refitter` configuration.
- A service without a spec gets a hand-written Refit interface (Apprise: `IAppriseApi`).
- Cross-cutting HTTP concerns are `DelegatingHandler` subclasses (for example
  `HttpLoggingHandler`), not per-call code.

ADR-013 owns the generator choice for all OpenAPI clients. Generated DTOs carry no round-trip
guarantee; gateways provide it (ADR-005).

## Rejected Options

- Refit with hand-written interfaces and DTOs: keeps the change-blind DTOs.
- RestEase: single maintainer, Newtonsoft by default.
- Stay on Flurl: no generated contracts and harder test doubles.

## Consequences

- Upstream API changes surface as compile errors after the spec is updated.
- Refit interfaces are mocked directly with NSubstitute.
- Generation adds a build step per API library.

## History

- 2026-02-26: Replace Flurl with Refit; generate Sonarr and Radarr clients with Refitter.
- 2026-03-03: Flurl removed from the codebase.
